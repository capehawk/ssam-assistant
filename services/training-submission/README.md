# 개인 계정 연수 제출 시연 서버

독립 GAS 서비스입니다. 쌤비서 설치판은 PDF와 연수 정보를 제출하고 담당자는 웹 확인함에서 확인완료/보완요청을 저장합니다. 개인 화면의 새로고침으로 결과를 조회합니다. 합성 데이터 전용이며 학교 포털 전체·NEIS 등록·공식 결재를 구현하지 않습니다.

## 파일과 경계

- `core.js`: 인증된 principal을 받는 순수 업무 규칙. SSAM·Drive·Sheets 의존 없음.
- `application.js`: 임시 인증, 오류 envelope, 잠금 경계.
- `gas-adapters.js`: Sheets 레코드/요청 영수증, 비공개 Drive 증빙.
- `gas/entry.gs`: GAS 진입점·설정. `gas/Reviewer.html`: 담당자 화면.
- `memory.js`, `fixtures.js`: 로컬 합성 시연과 검증.
- `CONTRACT.md`: 앱·서버의 전송 계약.

`node services/training-submission/build.mjs`로 `dist/`의 배포 파일 4개를 생성합니다. 생성 파일은 소스 수정 후 다시 빌드합니다. 테스트: `node --test tests/unit/training-service*.test.mjs`. 담당자 브라우저 테스트: `node tests/e2e/training-reviewer.mjs` (Playwright 설치 필요).

## 개인 Google 계정 배포

1. 개인 계정으로 Drive와 Apps Script에 로그인합니다. 여러 계정이 섞이면 별도 브라우저 프로필을 사용합니다. 지정 저장 폴더의 **공유 → 일반 액세스 → 제한됨**을 확인하고 불필요한 지정 사용자 권한도 제거합니다. 하위 폴더만 만들면 비공개가 되는 것으로 간주하지 않습니다. 이 구현은 개인 배포자가 해당 상위 폴더의 소유자여야 합니다. 소유자가 다르면 개인 계정 소유의 제한된 폴더를 준비합니다. 기존 교직원 시트를 복사하지 않습니다.
2. 같은 개인 계정으로 독립 Apps Script 프로젝트를 만들고 저장 위치/프로젝트 공유도 제한됨으로 확인합니다. `dist/Training.gs`, `dist/entry.gs`, `dist/Reviewer.html`, `dist/appsscript.json`의 내용을 같은 이름의 파일에 복사합니다. 프로젝트 설정에서 매니페스트 표시를 켜면 `appsscript.json`을 편집할 수 있습니다.
3. 프로젝트 설정의 Script Properties에 다음을 입력합니다. 실제 값은 공개 소스·PR·채팅에 붙이지 않습니다.

| 이름 | 값 |
| --- | --- |
| `PARENT_FOLDER_ID` | 제한된 개인 계정 소유 폴더 ID |
| `DEPLOYER_EMAIL` | 지금 배포하는 개인 계정 이메일 |
| `PRIVATE_FOLDER_CONFIRMED` | 공유와 계정을 직접 확인한 뒤 `true` |
| `TRAINING_AUTH_JSON` | 아래에서 생성한 검증값 배열 |

4. 로컬 터미널에서 `node services/training-submission/tools/create-credentials.mjs`를 직접 실행합니다. 출력의 `TRAINING_AUTH_JSON` 제목 바로 다음 줄을 대괄호까지 포함하여 같은 이름의 Script Property에 입력합니다. `PRIVATE TOKENS` 아래 인증값은 교사 A/B/담당자에게 각각 따로 전달합니다. 프로그램은 암호학적 난수 32바이트로 임시 인증값을 만들고 SHA-256 검증값만 서버에 저장하며 기본 만료는 24시간입니다. 출력은 비밀이므로 저장소·스크린샷·채팅·로그 공유에 넣지 않습니다. 이 에이전트는 실제 인증값을 생성하거나 수집하지 않았습니다.
5. 편집기에서 `setupDemo_`를 선택하여 실행하고 개인 계정의 최초 OAuth 승인을 완료합니다. `spreadsheets`는 제출 시트, `drive`는 증빙과 공유 확인, `userinfo.email`은 실제 배포자 확인에 사용합니다. 이 함수는 비공개 폴더·계정을 다시 검사하고 새 시트와 증빙 폴더를 만든 뒤 `SPREADSHEET_ID`, `EVIDENCE_FOLDER_ID`를 속성에 저장합니다. 반복 실행은 기존 저장소와 내용을 유지합니다. 실행 중 실패하면 속성을 확인하고 같은 함수를 재실행합니다. 인증이 설정되지 않은 서버는 모든 업무 요청을 거절합니다.
6. **배포 → 새 배포 → 웹 앱**, 실행 사용자=본인(배포자), 접근 권한=모든 사용자로 배포합니다. 계정/정책상 해당 옵션이 없으면 실제 배포를 완료했다고 간주하지 않습니다. 웹 접근 허용은 Drive 공개 공유와 별개이며 모든 데이터 요청은 앱 인증을 거칩니다. 배포 화면에서 받은 `/exec` URL을 사용합니다(`/dev`는 지원하지 않음).
7. Windows 설치판의 연수 화면에서 `/exec` 주소와 교사 인증값을 입력합니다. 담당자는 같은 `/exec` 주소를 브라우저에서 열고 담당자 인증값을 입력합니다. 인증값은 URL에 넣지 않습니다. 담당자 페이지는 `google.script.run`, 설치판은 제한된 Tauri 명령을 사용합니다. 일반 웹판에서 GAS 직접 fetch/CORS 지원을 보장하지 않습니다.

## 시연과 실제 배포 smoke

시연 데이터: teacher-a, teacher-b, reviewer-a; 안전교육·개인정보보호·아동보호 및 묶음. PDF는 합성 이수증만 사용합니다. 담당자에게 보여 주는 텍스트는 HTML로 삽입하지 않습니다.

1. 교사 A가 PDF/수동 입력 결과를 검토하고 제출 → 제출 ID와 확인대기 표시를 확인합니다.
2. 교사 B의 본인 목록에서 A 자료가 없고, A의 submissionId로 evidence/revise를 요청해도 거절되는지 확인합니다. 교사 인증으로 reviewQueue/review도 거절되어야 합니다.
3. 담당자는 PDF를 내려받아 확인하고 보완요청 의견을 저장합니다. A가 새로고침하여 의견/버전 2를 확인하고 수정 PDF를 재제출하여 확인대기/버전 3을 확인합니다.
4. 담당자가 확인완료 → A 새로고침에 확인완료/버전 4와 이전 이력이 표시됩니다. 오래된 버전 검토는 REVISION_CONFLICT여야 합니다.
5. 응답 유실을 재현해 같은 requestId/payload로 재시도하여 중복 제출·증빙이 생기지 않는지 확인합니다. 같은 ID/다른 내용은 REQUEST_CONFLICT여야 합니다. 5 MiB PDF와 5 MiB 초과 PDF의 경계를 확인합니다.
6. 인증 만료/폐기, 서버 저장소 접근 실패, 앱 네트워크 실패 때 성공 표시가 나오지 않는지 확인합니다. 마지막 상태는 최신 여부 미확인으로 남아야 합니다.

로컬 모의 검사와 실제 GAS 검사는 다릅니다. 배포 전 현재 상태는 **실제 개인 계정 GAS 배포·Google 리디렉션·학교망·Windows 설치판 통신 미검증**입니다. 테스트 통과를 실제 서버 성공이라고 쓰지 않습니다. 배포 smoke 후 사용한 앱/배포 버전·시각·결과만 기록하고 비밀값은 제외합니다.

## 저장, 복구와 시연 종료

한 제출의 상태/이력/요청 영수증은 같은 행의 JSON으로 함께 저장합니다. 각 셀은 40,000자 미만으로 나누고 `j:` 접두어로 수식 실행을 막습니다. 저장은 script lock 안에서 수행합니다. 한 제출 최대 50회 변경 및 JSON 총 1,000,000자 제한이 있으며 긴 내용은 그 이전에 한도에 도달할 수 있습니다. 소규모 시연을 위해 매번 전체 제출을 읽으므로 운영 규모용 DB가 아닙니다.

Drive와 Sheets는 원자적 트랜잭션이 아닙니다. 증빙 파일은 actor/request/payload의 해시 이름으로 재사용합니다. 시트 저장 결과가 불확실하면 파일을 삭제하지 않고 같은 요청 재시도로 영수증을 확인합니다. 이전 버전의 증빙 ID는 비공개 `evidenceHistory`에 보존하며 현재 UI는 최신 증빙만 조회합니다. 편집기의 `cleanupOrphanEvidence_`는 현재/이전 증빙 참조가 없는 생성 후 24시간 경과 파일만 휴지통으로 이동합니다. 진행 중인 업로드가 없는 시점에 실행합니다. 조회·JSON 해석에 실패하면 정리를 중단합니다.

업데이트는 빌드 후 배포 관리에서 새 버전으로 재배포합니다. 인증 폐기는 `TRAINING_AUTH_JSON`의 해당 항목 `revoked:true`, 전부 폐기는 `[]`로 바꾸며 이미 받은 로컬 PDF는 회수할 수 없습니다. 시연 종료 후 배포를 사용 중지하고 인증을 폐기한 뒤 별도로 만든 시트·증빙 폴더·프로젝트만 확인하여 정리합니다. 운영 인증/실자료에는 이 임시 인증을 재사용하지 않습니다.

## 학교 포털 M9로 이전

이 디렉터리와 계약/테스트를 함께 옮깁니다. M0 인증이 검증한 principal을 사용하도록 `createTokenAuthenticator`를 교체하고, M6 교직원/조직에 actorId와 역할을 연결합니다. 저장소·증빙 어댑터를 학교 저장소로 교체하며 상태 전이·revision·요청 중복 규칙을 유지합니다. 포털 메뉴/알림 UI는 새로 연결하고 SSAM 로컬 저장소·학년도를 서버 원본으로 사용하지 않습니다. 데모 인증/기록/환경 ID는 이전하지 않습니다. 다학교 권한·보존기간·백업·대상 배정·통계는 별도의 운영 설계 범위입니다.
