# 내 Google 계정에 연수 제출 시연 서버 만들기

쌤비서 앱과 제출 확인 서버는 별도입니다. 앱을 설치해도 서버가 자동 생성되지는 않습니다. 기존 시연 서버의 주소·인증값을 전달받았다면 그 서버에 연결하면 되며, 아래 과정은 **자기 저장소를 따로 만들 사람만** 진행합니다. 다른 배포자의 계정·인증값은 필요하지 않습니다.

이 안내는 합성 이수증을 사용하는 시연용입니다. 실제 학교 운영용 사용자 관리·조직별 권한·보존 정책을 갖춘 서비스는 아닙니다.

## 1. 준비물

- 연수 기능이 포함된 Windows 테스트판. 원본 공식 릴리즈에 이 기능이 포함됐는지는 별도로 확인하세요.
- 본인이 관리하는 Google 계정. 학교 계정은 관리자의 웹 앱 외부 접근 정책에 따라 배포가 제한될 수 있습니다.
- Node.js가 설치된 컴퓨터: 인증값 생성 도구 실행에만 사용합니다.
- 같은 버전의 `연수-시연서버.zip`. 압축을 풀면 `dist/`의 배포 파일 4개, `tools/create-credentials.mjs`, 이 안내, `demo-certificate.pdf`가 있습니다.

저장소에서 직접 받는 경우 `services/training-submission/`에 같은 자료가 있습니다. 이미 생성된 `dist/`를 쓰면 Git·Rust·clasp 설치나 앱의 로컬 빌드는 필요하지 않습니다.

## 2. 비공개 저장 폴더와 프로젝트

1. 해당 Google 계정으로 Drive에 새 시연 전용 폴더를 만듭니다.
2. 공유 설정의 일반 액세스를 **제한됨**으로 하고 불필요한 사용자 공유를 제거합니다. 본인이 소유한 폴더여야 합니다.
3. 폴더 주소 `https://drive.google.com/drive/folders/폴더ID`에서 폴더 ID를 기록합니다.
4. 같은 계정으로 [Apps Script](https://script.google.com/)에서 새 독립 프로젝트를 만듭니다. 여러 계정이 있으면 전용 브라우저 프로필을 사용하세요.
5. 기본 `Code.gs` 대신 `dist/Training.gs`, `dist/entry.gs`를 스크립트 파일로, `dist/Reviewer.html`을 HTML 파일로 복사합니다. 이름이 `Training.gs.gs`처럼 중복되지 않게 합니다.
6. 프로젝트 설정에서 매니페스트 파일 표시를 켜고 `appsscript.json`을 `dist/appsscript.json` 내용으로 바꿉니다. 저장합니다.

## 3. 스크립트 속성과 인증값

프로젝트 설정 → 스크립트 속성에 아래 값을 추가합니다.

| 속성 이름 | 입력할 값 |
| --- | --- |
| `PARENT_FOLDER_ID` | 위에서 만든 폴더 ID |
| `DEPLOYER_EMAIL` | 이 프로젝트와 폴더를 관리하는 Google 계정 이메일 |
| `PRIVATE_FOLDER_CONFIRMED` | 공유 상태를 확인한 후 `true` |
| `TRAINING_AUTH_JSON` | 아래 도구가 출력하는 검증값 배열 |

압축을 푼 폴더에서 터미널을 열고 실행합니다. 별도 패키지 설치는 필요하지 않습니다.

```sh
node tools/create-credentials.mjs
```

출력에는 서로 다른 두 종류의 값이 있습니다.

- 개인별 임시 인증값: `teacher-a`, `teacher-b`는 교사 앱에, `reviewer-a`는 담당자 웹 확인함에 입력합니다. 필요한 사람에게 해당 역할의 값만 직접 전달합니다.
- `TRAINING_AUTH_JSON`: 제목 다음의 배열 전체를 대괄호까지 복사해 같은 이름의 스크립트 속성에 저장합니다. 이 배열을 앱의 인증값 칸에 넣으면 안 됩니다.

기본 유효기간은 생성 후 24시간입니다. 며칠간 검토할 경우 배열의 각 `expiresAt`을 원하는 종료 시각으로 바꿔 저장할 수 있습니다. 시간대를 명시한 ISO 형식을 사용하세요. 예를 들어 **2026년 11월 30일 한국 시간 하루가 끝날 때까지**라면 `2026-12-01T00:00:00+09:00`입니다. 그 시각부터 만료됩니다. `tokenHash`·`actorId`는 그대로 유지하면 기존 인증값을 계속 사용할 수 있습니다. 속성 변경만으로 적용되며 재배포는 필요하지 않습니다.

도구를 다시 실행하면 새 인증값이 생성됩니다. 속성 배열을 새 출력으로 교체하면 이전 인증값은 사용할 수 없습니다. 원문 인증값을 분실했을 때는 해시로 복구할 수 없으므로 새로 발급합니다. 실제 값은 공개 저장소·공개 안내 문서에 넣지 않습니다.

## 4. 시연 저장소 초기화

`setupDemo_`는 웹 클라이언트가 호출할 수 없도록 이름 끝에 `_`가 붙어 있습니다. 편집기 실행 목록에 나타나지 않으면 임시 `Initialize.gs`를 만들고 아래 코드를 넣습니다. 실제 이메일이나 인증값을 코드에 쓰지 않아도 됩니다.

```javascript
function initializeDemo() {
  var owner = (PropertiesService.getScriptProperties().getProperty('DEPLOYER_EMAIL') || '').toLowerCase();
  var active = Session.getActiveUser().getEmail().toLowerCase();
  var effective = Session.getEffectiveUser().getEmail().toLowerCase();
  if (!owner || active !== owner || effective !== owner) throw new Error('배포자 계정의 편집기에서 실행하세요.');
  return setupDemo_();
}
```

1. 저장하고 필요하면 편집기를 새로고침합니다.
2. 함수 목록에서 `initializeDemo`를 선택해 실행하고 Google 권한 승인을 완료합니다.
3. 지정 Drive 폴더에 `Training submission demo` 시트와 `Training evidence demo` 폴더가 생성됐는지 확인합니다. 스크립트 속성에는 `SPREADSHEET_ID`, `EVIDENCE_FOLDER_ID`가 자동 기록됩니다.
4. 이 두 저장소의 일반 액세스도 제한됨인지 확인합니다.
5. **웹 앱으로 배포하기 전에 임시 `Initialize.gs`를 삭제하고 저장합니다.**

초기화는 기존 저장소와 내용을 유지합니다. 실패했을 때 새 프로젝트를 반복 생성하기보다 속성·소유 계정·공유 상태와 실행 오류를 먼저 확인하세요.

## 5. 웹 앱 배포와 연결

1. 배포 → 새 배포 → 유형 ‘웹 앱’을 선택합니다.
2. 실행 사용자는 **본인(배포자)**, 접근 권한은 외부 시연자가 접근 가능한 **모든 사용자**로 설정합니다. 해당 옵션이 없다면 계정 정책을 확인해야 합니다.
3. 배포 결과의 `https://script.google.com/macros/s/배포ID/exec` 주소를 기록합니다. 프로젝트 편집 주소나 `/dev` 주소는 앱에 넣지 않습니다. `/a/도메인/`이 들어간 주소가 아닌 위 형식의 배포 주소를 사용합니다.
4. 교사: Windows 앱 → 연수 → 내 필수연수 → 학교 제출 서버 연결에서 서버 주소와 교사 인증값을 입력합니다.
5. 담당자: 같은 서버 주소를 브라우저에서 열고 담당자 인증값을 입력합니다. 앱의 연수 현황판에서 담당자 웹 화면 링크로 이동할 수도 있습니다.

웹 앱 접근을 허용하기 위해 Drive 폴더를 공개할 필요는 없습니다. 공유 교사 인증값을 사용하면 같은 교사로 취급되고, 담당자 인증값은 시연 제출물의 조회·검토 권한을 줍니다.

## 6. 처음부터 끝까지 확인

1. 교사 A로 연결하고 동봉된 `demo-certificate.pdf`와 시연 연수 정보를 제출합니다.
2. 담당자 웹 확인함에서 제출물과 증빙을 확인한 뒤 확인완료 또는 보완요청을 선택합니다.
3. 교사 앱에서 결과 새로고침을 누릅니다. 확인완료된 연수는 해당 이수일의 학년도 체크리스트에 표시됩니다.
4. 교사 B로 연결했을 때 A의 제출물이 보이지 않는지 확인합니다.

## 7. 자주 막히는 부분과 종료

| 증상 | 확인할 내용 |
| --- | --- |
| 함수 없음 | 파일 저장 후 새로고침, 위 임시 초기화 함수 사용 |
| 인증값 없음·만료·폐기 | 앱에는 원문 인증값, 속성에는 해시 배열을 넣었는지와 `expiresAt` 확인 |
| 저장소 설정 오류 | 배포 계정·폴더 소유자·속성 이름·제한됨 상태·초기화 완료 확인 |
| 서버 주소 오류 | `/macros/s/배포ID/exec` 형식 확인 |
| 브라우저에서는 열리는데 제출 실패 | 연수 기능이 포함된 Windows 앱 사용 여부와 배포 접근 권한 확인 |
| 수정한 서버 코드가 반영되지 않음 | 배포 관리에서 새 버전으로 업데이트. 속성만 변경한 경우에는 재배포 불필요 |

시연 종료 후 인증 항목을 `revoked:true`로 바꾸거나 `TRAINING_AUTH_JSON`을 `[]`로 바꿔 접근을 폐기할 수 있습니다. 더 이상 서버를 쓰지 않으면 웹 앱 배포를 사용 중지하고 시연 저장 자료를 정리합니다. 종료 시각과 자료 정리 책임은 각 서버 배포자가 관리합니다.
