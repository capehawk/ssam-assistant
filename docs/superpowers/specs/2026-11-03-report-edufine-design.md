# 쪽지 첫 줄 · 이음 붙임 · 에듀파인 차례로 붙여넣기 · 계획 › 결과 보고 설계

날짜: 2026-11-03 · 대상 버전: 0.15.0 · 앞선 설계: `2026-11-02-purchase-oneshot-notes-design.md`(쪽지·품의), 나이스 자동 붙여넣기(`src-tauri/src/neis.rs`)

## 1. 정한 것 (선생님 말·답)

| 요청 | 정한 것 |
|---|---|
| 1. 창체 전체복사 → 나이스 1번 칸 Ctrl+V → 끝 번호까지(Tab 3번) | **이미 됨**(창체 결과 화면 [전체복사], Tab 기본 3번, 창체 설정 따로). 손대지 않음 |
| 2. 쪽지 본문 시작 | 본문 첫머리를 **「안녕하세요 선생님.」**으로 고정. 이음은 제목 칸이 없으므로 **제목 줄부터** 쓰고 그다음에 인사 |
| 3-1. 붙임 파일 복사가 이음 쪽지에 안 붙음 | 이음은 **PC에 설치한 프로그램**. 컴퓨터 제어가 이 대화에서 켜져 있지 않아 실제 이음으로 시험하지 못함 → 세 길을 함께 둠(4장) |
| 3-2. 나이스·에듀파인을 웹브라우저에서 | **에듀파인 품의 입력**, **에듀파인 공문 기안 입력**. 칸 하나 누르고 Ctrl+V 하면 다음 것이 들어가는 「차례로 붙여넣기」. **저장·결재·상신은 늘 선생님이 누름** |
| 4. 계획 › 결과 보고 공문 자동 작성 | **공문 + 결과 보고서**(사진이 들어간 한글·워드·PDF). 계획서·공문·작년 보고서 파일, 한 일 메모, 사진을 넣으면 씀. **사진도 AI가 봄** |

## 2. 쪽지 첫 줄 (요청 2)

`composeMessage`가 돌려주는 `body`:

```
[연수 안내] 2026 AI 활용 수업 연수

안녕하세요 선생님.
2026 AI 활용 수업 연수를 아래와 같이 안내드립니다.

□ 일시: …
```

- 첫 줄은 `title`(「[종류] 제목」, 다시 안내면 「[다시 안내] 제목」)과 같음. 제목이 비면 「[연수 안내]」만.
- 인사는 늘 「안녕하세요 선생님.」(전에는 「선생님들, 안녕하세요.」).
- 화면: 쪽지 카드의 따로 있던 「제목」 칸·[복사]를 없애고 **본문 하나**만(제목은 본문 첫 줄). [모두 복사]는 본문을 그대로 복사. 왼쪽 「칸」의 제목은 그대로(고치면 본문 첫 줄이 바뀜).
- 최근 쪽지 목록 제목은 지금처럼 `title`.
- 본문을 손으로 고쳤으면(edited) 지금처럼 그대로 두고 [칸으로 다시 맞추기].

## 3. 차례로 붙여넣기 (요청 3-2, Windows 앱)

### 3.1 하는 일
「에듀파인에 차례로 붙여넣기」를 누르면 앱이 Ctrl+V를 잠깐 맡음(나이스 자동 붙여넣기와 같은 길). 브라우저에서 칸을 누르고 Ctrl+V를 누를 때마다 **다음 조각**을 클립보드에 넣고 그 칸에 붙여 넣음.

- 조각은 글 그대로(줄바꿈 그대로) — 품의 사유·공문 본문이 여러 줄이어도 됨(웹 한글 기안기도 보통 붙여넣기는 받음).
- 넣는 방식은 **붙여넣기만**(글자 입력은 쓰지 않음: 여러 줄·긴 글, 기안기).
- 브라우저가 아닌 창, 이 앱 창에서 누른 Ctrl+V는 평소처럼 붙여넣기(나이스와 같음). 「브라우저가 아닌 창에서도 쓰기」를 켜면 가상 PC 등에서도.
- 준비한 뒤 **15분** 동안 쓰지 않으면 풀림(붙일 때마다 다시 15분). 마지막 조각을 붙이면 「다 넣었어요 · 내용을 확인하고 저장은 선생님이 눌러 주세요」.
- 패널: 조각 목록(제목 · 품의 사유 · 산출 내역 …), **다음에 들어갈 조각**을 굵게, [◀ 앞으로][건너뛰기 ▶], 목록의 조각을 누르면 그 조각부터. [닫기]를 누르면 풂.
- 나이스 붙여넣기와 Ctrl+V를 같이 맡지 않음: 하나를 준비하면 다른 준비는 풀림.
- 웹판: 단추 대신 조각마다 [복사]만(지금처럼).

### 3.2 조각
| 곳 | 조각 |
|---|---|
| 품의 › 새 품의 초안 | 제목 → 품의 사유 → 산출 내역. 산출 내역은 [표 한 번에](지금의 「표 복사」 글, 엑셀처럼 붙여 넣는 표용) 또는 [칸마다](품목마다 품명·규격·단위·수량·단가 한 칸씩). 고른 것은 기억 |
| 결과 보고 공문 (5장) | 제목 → 본문 |
| 쪽지 | 쓰지 않음(이음은 브라우저가 아님, 본문 하나) |

### 3.3 Rust (`neis.rs`에 더함)
- `queue_arm(items: Vec<String>, start: usize, any_window: bool) -> Armed { gen, secs }`: 빈 조각 빼지 않음(빈 조각은 건너뜀 표시), 조각 50개·한 조각 2만 자까지.
- `queue_goto(index: usize)`: 다음 조각을 바꿈. `neis_disarm`이 둘 다 풂.
- Ctrl+V(브라우저): `Clip(item) → (Ctrl이 눌려 있으면 V만, 아니면 Ctrl+V)`, 맡은 Ctrl+V를 잠깐 내려놓고 보냄(나이스 「평소처럼 붙여넣기」와 같은 방법) → 다음 조각으로. 이벤트 `neis-paste`에 `{ state: 'queue', gen, done: 붙인 조각 번호+1, total }`, 끝이면 `state: 'end', reason: 'finished'`.
- 빈 조각은 붙이지 않고 건너뜀(Ctrl+V 한 번에 다음 비지 않은 조각).
- 계획(plan)은 순수 함수 `queue_plan(text, ctrl_held) -> Vec<Step>`로 시험.

## 4. 이음 붙임 (요청 3-1)

이음 쪽지 창이 무엇을 받는지 모르므로 셋을 함께 둠. 모두 「쌤비서 쪽지 붙임/날짜 제목」 폴더의 파일만.

1. **[붙임 파일 복사] 를 탐색기와 같게**: 지금은 파일 목록(CF_HDROP) 하나만 넣음. 탐색기 Ctrl+C처럼 쉘 데이터 개체(`SHCreateShellItemArrayFromIDLists` → `BindToHandler(BHID_DataObject)`)에 「Preferred DropEffect = 복사」를 넣어 `OleSetClipboard` + `OleFlushClipboard`(앱을 꺼도 남음). 탐색기에서 복사한 파일을 이음에 붙여 넣을 수 있다면 이것도 됨.
2. **끌어 놓기**: 붙임 목록의 파일 줄(과 [모두 끌기])을 마우스로 눌러 끌면 그 파일이 탐색기에서 끄는 것과 똑같이 끌림(`DoDragDrop`, 앱 메인 스레드). 이음 쪽지 창에 놓으면 첨부. 누를 때 파일을 폴더에 먼저 저장해 둠(넣은 파일이 바뀌면 다시 저장).
3. **[폴더 경로 복사]**: 이음의 [파일 첨부] 창 「파일 이름」 칸에 Ctrl+V → Enter 하면 그 폴더가 열림. 파일이 하나면 그 파일 경로를 복사(바로 첨부).

- 안내 글: 「이음 쪽지 창에 Ctrl+V가 안 되면 파일 줄을 끌어 놓거나, [파일 첨부] 창에서 경로를 붙여 넣으세요.」
- 웹판은 지금처럼 안내만.
- **시험의 한계**: 실제 이음에서는 시험하지 못함(컴퓨터 제어 꺼짐). 선생님이 해 보고 알려 주면 맞춤. Windows 쪽 코드는 `cargo check`(Windows 대상)로만 확인, 실제 동작은 릴리즈 빌드 뒤 선생님 PC에서.

## 5. 계획 › 결과 보고 (요청 4)

### 5.1 자리와 넣기
- 계획 메뉴에 탭 **「결과 보고」**(id `report`) — 연간계획 · 행사계획 · 학급운영계획 · 결과 보고.
- 넣기(한 곳에 끌어 놓기·고르기·글 붙여 넣기):
  - 문서(한글·PDF·워드·글): 종류를 짐작해 칩으로 — **계획서 · 관련 공문 · 작년 보고서 · 기타**(이름·글에 「결과」「보고」 + 작년이면 작년 보고서, 「공문」·문서번호 꼴이면 공문, 나머지 계획서). 칩을 눌러 바꿈.
  - **한 일** 메모(무엇을 했는지·참여 인원·잘된 점·아쉬운 점 등, 줄글이면 됨).
  - **사진** 최대 12장(쓸 때 긴 변 1600px JPEG로 줄임). 사진마다 설명 칸(AI가 채움, 고칠 수 있음), ×로 빼기, 차례 바꾸기(◀▶).
  - 행사계획에서 [결과 보고 쓰기]를 누르면 그 행사의 이름·날짜·장소·대상·계획서 글·설문 결과 보고서를 넣은 채로 열림.
- 문서 글은 `cleanSheet`로 명단·전화번호 줄을 빼고 AI로 보냄(쪽지와 같음). 사진은 긴 변 1024px로 AI에 보냄(선생님 동의). **원본 파일과 사진은 저장하지 않음**(이 화면에만, 앱을 다시 켜면 다시 넣기). 글·칸·사진 설명은 저장.

### 5.2 AI 한 번 (업무 `report`, 업무별 AI에 「결과 보고」 줄)
보내는 것: 종류별 글(계획서·공문·작년 보고서·기타 각 최대 6천 자), 한 일 메모, 사진(차례대로).
받는 JSON:
```json
{"name":"2026 과학의 날 행사","related":[{"no":"○○초-1234","date":"2026-03-10","title":"2026 과학의 날 행사 운영 계획"}],
 "period":{"start":"2026-04-21","end":"","time":""},"place":"","target":"","count":"",
 "summary":"주요 내용 한 줄",
 "sections":[{"h":"목적","lines":["…"]},{"h":"추진 내용","lines":["…"]},{"h":"성과","lines":["…"]},{"h":"반성 및 개선 방안","lines":["…"]}],
 "photos":["사진 1 설명","사진 2 설명"]}
```
- 작년 보고서가 있으면 **그 짜임(소제목 차례)과 문체를 따르고** 올해 내용으로. 없으면 위 네 소제목.
- 한 일 메모에 없는 성과·숫자는 지어내지 않음. 사람 이름·전화번호는 쓰지 않음.
- 날짜는 `YYYY-MM-DD`(연도 없으면 학년도), 쪽지의 날짜 읽기를 같이 씀.

### 5.3 앱이 맞추는 것
**결과 보고 공문** (제목 + 본문, 에듀파인 기안에 붙여 넣을 꼴):
```
제목: 2026 과학의 날 행사 운영 결과 보고

1. 관련: ○○초-1234(2026. 3. 10.) 「2026 과학의 날 행사 운영 계획」
2. 위 호와 관련하여 2026 과학의 날 행사 운영 결과를 다음과 같이 보고합니다.
  가. 일시: 2026. 4. 21.(화)
  나. 장소: 본교 강당
  다. 대상: 전교생(320명)
  라. 주요 내용: …

붙임  2026 과학의 날 행사 운영 결과 보고서 1부.  끝.
```
- 관련이 둘 이상이면 「1. 관련: 가. … 나. …」, 없으면 관련 줄 없이 「1. 2026 … 결과를 다음과 같이 보고합니다.」.
- 빈 칸(장소 등)은 빼고 가·나·다를 다시 매김. 붙임 이름은 보고서 제목.

**결과 보고서** (`{ title, blocks }` → 한글·워드·PDF):
- 제목 「(행사 이름) 운영 결과 보고서」.
- 「1. 개요」 표(구분 | 내용: 행사명 · 일시 · 장소 · 대상(인원) · 관련).
- 「2.~」 소제목마다 줄(「- 」 붙임). 
- 마지막 「N. 사진 자료」: **사진 블록**(한 줄에 2장, 사진 밑에 설명).
- 화면: 공문 카드(제목·본문 고치기, [복사], [모두 복사], Windows 앱 [에듀파인 기안에 차례로 붙여넣기]) · 보고서 카드(개요 칸·소제목별 글 고치기·사진 설명, [한글로 내려받기 ▾]).
- 최근 결과 보고 20개(글만, 다시 열기).

### 5.4 문서에 사진 (새 블록)
`{ type: 'photos', items: [{ bytes: Uint8Array(JPEG), w, h, caption }] }`
- **한글(hwpx)**: `BinData/imageN.jpg` + `content.hpf`의 `<opf:item id="imageN" href="BinData/imageN.jpg" media-type="image/jpg" isEmbeded="1"/>` + 2열 표의 칸마다 `hp:pic`(글자처럼 취급, 칸 너비에 맞춘 크기, 가로세로 비율 그대로) 문단과 설명 문단.
- **워드(docx)**: `word/media/imageN.jpeg`, 관계(rId), `[Content_Types]`의 jpeg, 2열 표 칸마다 `w:drawing`(`wp:inline`).
- **PDF**: 인쇄 HTML의 2열 표에 `<img src="data:image/jpeg;base64,…">`.
- 사진이 없으면 블록을 건너뜀. 다른 메뉴 문서는 그대로.
- 시험: hwpx·docx 안의 파일·XML 모양(단위 시험), docx는 LibreOffice로 PDF를 만들어 사진이 보이는지 한 번 확인(손 확인). 한글 프로그램으로는 확인 못 함 → 선생님 확인.

## 6. 하지 않는 것
- 에듀파인 저장·결재·상신, 나이스 저장 누르기(늘 선생님).
- 이음 쪽지 창을 앱이 찾아 직접 넣기(창 구조를 모름).
- 사진 얼굴 가리기(선생님이 고른 사진을 그대로 씀).
- 결과 보고의 검토 AI(필요하면 뒤에).

## 7. 시험
- 단위: `composeMessage` 첫 줄·인사, `queue_plan`(Rust 시험, 릴리즈 CI에서), `reportPrompt`·`normReport`·`composeReportLetter`·`reportDoc`, hwpx·docx 사진 블록, 문서 종류 짐작.
- e2e: 쪽지(본문 첫 줄·제목 칸 없음·모두 복사), 품의 차례로 붙여넣기 패널(가짜 `__TAURI__`로 `queue_arm` 인자·이벤트), 쪽지 붙임 끌기·경로 복사(가짜 `__TAURI__`), 결과 보고 탭(파일·메모·사진 → AI 요청에 그림 · 공문·보고서 · 내려받기 · 다시 열기 · 행사계획에서 열기).
