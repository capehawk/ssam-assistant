# 업무별 AI와 검토 AI 설계

날짜: 2026-11-02 · 요청: 「AI 에이전트를 업무별로 달리 사용하거나, 하나는 메인, 하나는 서브 해서 하나로 돌리고 하나는 검토하는 형식으로 역할을 나누게 기능을 구현할 수 있어?」

## 1. 선생님이 고른 것

- 방식: **둘 다** — 업무마다 쓰는 AI(메인 AI)를 다르게 정할 수 있고, 메인 AI가 쓴 것을 다른 AI(검토 AI)가 한 번 더 봄.
- 정하는 곳: **각 업무 메뉴 안에서** (설정 › AI에는 기본값만).
- 검토하는 곳: **채점 · 평어·행특·창체 문장 · 계획 초안 · 학생 피드백·알림글** 모두.
- 의견이 다르면: **두 의견을 보여 주고 선생님이 고름**. 고르기 전에는 메인 안 그대로.
- 검토량: **필요한 곳만** (확신 낮은 칸·규칙에 걸린 문장 등). 사용량 대략 1.2~1.5배.

## 2. 말

- **메인 AI**: 그 업무를 처음 쓰거나 채점하는 AI. 업무마다 정하지 않으면 **기본 AI**(지금 설정 › AI에서 고른 것).
- **검토 AI**: 메인 AI의 결과 중 필요한 곳만 다시 보는 AI. 업무마다 켜고 끔. 업무에서 따로 고르지 않으면 **기본 검토 AI**(설정 › AI, 처음엔 정하지 않음).
- **AI 하나** = `{ engine, model }` (engine: claude · gemini · openai · upstage). 키는 지금처럼 회사마다 설정 › AI에 넣고, **키를 넣은 회사만** 고를 수 있음. 같은 회사의 다른 모델도 따로 고를 수 있음(예: Sonnet이 쓰고 Opus가 검토).
- **업무 4개**

| 업무 키 | 이름 | 쓰는 곳 |
|---|---|---|
| `grade` | 채점 | 단원평가 채점, 평가지 채점(채점·수준 맞추기) |
| `writing` | 평어·행특·창체 | 교과 평어, 행동특성, 창의적 체험활동, 평가지 채점의 평어, 대명사 고치기 |
| `plan` | 계획 초안 | 연간계획(초안·지침 점검), 행사계획(구성안·문서), 학급운영계획(초안·지침 점검·평가 표 읽기) |
| `notes` | 피드백·알림 | 단원평가 잘한 점·격려, 주간학습안내 알림 |

  그 밖의 AI 일(견적서·진도표·문서 읽기, 번호 읽기, 결과 보고서 등)은 **기본 AI**로, 검토 없음.
- `account`(claude.ai 안의 「Claude 계정」)를 쓰면 업무별 AI·검토는 쓸 수 없고 지금처럼 하나로(메뉴의 AI 줄에 그렇게 적음).

## 3. 정하는 곳

### 3.1 메뉴 안의 「AI 줄」
각 업무 화면 위쪽(또는 AI 단추 옆)에 한 줄: `AI: Claude Sonnet 5.5 · 검토: Claude Opus 5.5 [바꾸기]` (검토를 끄면 `검토 끔`).
[바꾸기] → 창:
- **이 업무의 AI**: 「기본 AI 따름(지금: …)」 또는 키를 넣은 회사의 모델 고르기.
- **검토 AI로 한 번 더 보기** 켜기·끄기.
- **검토 AI**: 「기본 검토 AI 따름(지금: …)」 또는 모델 고르기. 기본 검토 AI도 없으면 고르라고 안내(고르기 전에는 검토하지 않음).
- 안내: 「검토를 켜면 AI 사용량이 대략 1.2~1.5배예요」, 검토 AI가 메인과 **다른 회사**이고 업무가 채점이면 「학생 답안 그림(이름 가림)이 두 회사로 가요」.

같은 업무를 쓰는 메뉴는 같은 설정을 봄(예: 단원평가와 평가지 채점의 AI 줄은 모두 `grade`).

### 3.2 설정 › AI
- 지금 칸(회사·키·모델 = **기본 AI**) 아래에 **기본 검토 AI**(검토 안 함 / 키를 넣은 회사의 모델).
- **업무별 설정 한눈에**: 업무 4개의 메인·검토 요약과 [기본으로 되돌리기].

### 3.3 저장
- 키 `ai-roles`(학년도와 상관없음, `years.js` GLOBAL): `{ review: AI|null, tasks: { grade|writing|plan|notes: { main: AI|null, reviewOn: bool, review: AI|null } } }`.
- 키가 없어졌거나 모르는 모델이면 그 칸은 없는 것으로 봄(기본으로).

## 4. AI 부르기

- `core/ai-roles.js`: `pick(task, role)` → AI 또는 `null`.
  - `main`: 업무의 `main`(키 있음) → 아니면 `null`(= 기본 AI).
  - `review`: `reviewOn`이 아니면 `null`. 업무의 `review`(키 있음) → 기본 검토 AI(키 있음) → 없으면 `null`.
  - `account` 엔진이면 늘 `null`.
- `core/ai.js`: `generate(prompt, { task, role, … })`, `generateJSON(…)`도 같은 옵션. `task`가 있으면 `pick`으로 고른 AI를 옛 화면의 `generate`에 `use`로 넘김.
- 옛 화면(`evaluate.js`) `generate(prompt, { use, task, role, … })`: `use`가 있으면 그 회사·모델로(`callApi(provider, …, { model })`), 없고 `task`가 있으면 `SSAM.aiRoles.pick(task, role)`, 그것도 없으면 지금처럼 기본 AI. 업스테이지 그림 읽기도 실제로 부르는 회사 기준.
- 옛 화면 안의 AI 부르기 10곳에 `task`를 붙임(평어 1 · 행특 1 · 평가지 채점 2 + 평어 2 · 창체 3 · 대명사 1).
- 새 메뉴의 AI 부르기에도 `task`를 붙임(단원평가 채점·피드백, 연간·행사·학급운영계획 초안·지침 점검, 주간학습안내 알림).
- 오류 안내는 실제로 부른 회사 이름으로.

## 5. 검토 (필요한 곳만)

모든 검토는 **메인 결과가 나온 뒤** 같은 차례에서 이어서 하고, 검토가 끝나기 전에도 메인 결과는 그대로 쓸 수 있음. 검토 AI가 실패하면(키·한도·연결) 메인 결과는 그대로, 그 자리에 「검토하지 못했어요」만(일을 막지 않음, 남은 검토는 그만둠).

| 업무 | 검토하는 것 | 검토 AI에 보내는 것 | 검토 AI 답 |
|---|---|---|---|
| 단원평가 채점 | 메인이 `sure: false`라 한 칸 + 서술형 부분 점수(0점도 만점도 아님) 칸 | 같은 학생 그림(이름 가림, 메인과 같은 그림) + 그 문항들의 정답표 줄 | 문항마다 `read`·`points`·`why` |
| 평가지 채점 | 「읽기 어려움」인 학생 + 수준 경계(나눈 수준이 바뀌는 바로 위·아래 학생) | 같은 그림 + 채점 기준(메인과 같음) | `score`·`summary` |
| 평어·행특·창체 | 쓴 문장 10개씩 한 번에 | 문장들 + 그 평가 정보(성취기준·평가 요소·활동) — 학생 이름 없음 | 문제 있는 문장만 `{ i, problem, fix }` (끝맺음·분량·성취기준과 다름·이름·개인정보·과장) |
| 계획 초안 | 초안 전체 한 번 | 초안 + 올해 지침 요약(초안 쓸 때와 같은 것) | 칸마다 `{ section, problem, fix }` (빠진 지침·작년 날짜·숫자 남음·서로 맞지 않음) |
| 피드백·알림 | 잘한 점·격려 전체 한 번, 주간 알림 한 번 | 그 글들 + 번호·점수(지금 보내는 것만) | 고칠 것만 `{ no/day, field, problem, fix }` |

같은지 다른지:
- 단원평가: 검토 `read`가 메인과 같은 답(정답 맞추기 규칙으로 같은 판정)이고 `points`도 같으면 **같음** → 그 칸은 확인할 칸에서 빠짐(두 AI가 같게 봄). 다르면 **두 의견**.
- 평가지 채점: 점수 차이가 10점 이상이면 **두 의견**.
- 글(평어·계획·피드백·알림): 검토 AI가 문제를 적은 것만 **두 의견**.

## 6. 두 의견 보여 주기

- 그 칸·문장·문단을 **노랗게** 하고 「검토 의견」 표시. 누르면(또는 펼치면): **메인 안 / 검토 안**과 검토 AI가 적은 까닭, [검토 안 쓰기] [그대로 두기].
- 고르면 표시가 사라지고 고른 것을 기억(`done: 'review' | 'main'`). 선생님이 그 칸·문장을 손으로 고치면 검토 의견은 사라짐.
- 화면마다 위쪽에 「검토 의견 N개」와 [다음 의견] (단원평가 확인 표의 「다음 확인할 칸」처럼).
- 데이터
  - 단원평가 문항 칸: `rv: { read, points, why, agree, done }`
  - 평가지 채점 학생: `rv: { score, summary, done }`
  - 평어·행특·창체 문장: `rv: { problem, fix, done }`
  - 계획: `plan.review = [{ section, problem, fix, done }]`
  - 피드백: 학생 `rv: { field, problem, fix, done }`, 주간 알림: 칸 `rv`

## 7. 지키는 것

- 검토 AI에도 메인과 **같은 것만** 보냄(이름 가린 그림, 번호·점수, 이름 없는 글). 새로 보내는 정보 없음.
- 검토는 메뉴의 AI 줄에서 켠 업무에서만. 처음엔 모두 꺼짐(지금과 똑같이 동작).
- 키는 지금처럼 이 컴퓨터에만, 백업 파일에 넣지 않음(`ai-roles`에는 회사·모델 이름만).
- 업무별 AI를 정해도 그 회사 키가 지워지면 기본 AI로 돌아감(AI 줄에 「키가 없어 기본 AI로」).

## 8. 만드는 차례

1. 공통: `core/ai-roles.js`(저장·`pick`·AI 줄·창), 설정 › AI의 기본 검토 AI·업무별 한눈에, `core/ai.js`와 옛 `generate`의 `use`/`task`, 모든 AI 부르기에 `task` 붙이기 → 업무별 메인 AI가 모든 곳에서 동작.
2. 두 의견 공통 모양(노란 표시·창·[다음 의견]).
3. 단원평가 채점 검토.
4. 계획 초안 검토(연간·학급운영 초안, 행사 계획서).
5. 피드백·알림 검토(단원평가 잘한 점·격려, 주간학습안내 알림).
6. 평어·행특·창체 문장 검토(옛 화면).
7. 평가지 채점 검토(옛 화면).
8. 문서(README·PRD·릴리즈 노트)·전체 시험.

## 9. 시험

- 단위: `pick`(키 없음·모르는 모델·account·기본 검토 AI), 업무별 설정 저장·되돌리기, 검토 프롬프트·답 읽기(`normReview…`), 같은지 판정(단원평가 답·점수, 평가지 10점).
- 화면: 가짜 AI가 **모델 이름**으로 메인·검토를 구분(같은 회사 다른 모델).
  - AI 줄에서 업무별 AI를 바꾸면 그 업무의 요청만 그 모델로 감, 다른 업무는 기본 AI.
  - 검토를 켜면 필요한 곳만 검토 요청(단원평가: 확신 없음·부분 점수 칸만, 그 학생 그림 포함), 같으면 확인할 칸이 줄고, 다르면 두 의견 → [검토 안 쓰기]로 바뀜.
  - 검토 AI가 실패해도 메인 결과는 그대로·「검토하지 못했어요」.
  - 평어·계획·피드백·평가지 채점도 각각 두 의견과 고르기.

## 10. 하지 않는 것

- 셋 이상 AI·여러 번 주고받는 토론, AI끼리 자동으로 고쳐 쓰기.
- 그 밖의 AI 일(문서·견적서·번호 읽기 등)의 검토.
- 품의(다른 선생님 담당) — 공통 `task` 옵션만 쓰면 붙일 수 있음.
