# 채점 AI 요청 손보기 (공통 부분 캐시 · 동시 채점 · 사용량) 설계

날짜: 2026-11-03 · 대상 버전: 0.14.0 · 앞선 설계: `2026-11-02-ai-roles-design.md`(업무별·검토 AI), `2026-11-02-activity-grading-design.md`(활동지)

## 1. 정한 것 (선생님 답)

| 질문 | 답 |
|---|---|
| 최적화 범위 | 미뤄 둔 11개(끝남) + **AI 비용·속도**. 앱 켜기는 재 보니 이미 빨라(Windows 앱 0.2~0.55초, 웹판 학교망 첫 방문 0.84초) 손대지 않음 |
| 접근안 | **「AI 요청 손보기」**: 채점 세 곳(평가지·단원평가·활동지)과 그 검토 AI에서 공통 부분 캐시, 단원평가·활동지 동시 채점 늘리기, 채점 뒤 사용량 한 줄 |

## 2. 잰 것 (2026-11-03)

- 평가지 채점(`evaluate.js` `grGrade`): 학생마다 `images: [...학생 그림, ...기준 그림(최대 6장)]`. 기준 그림이 뒤에 있어 AI 회사가 같은 앞부분을 알아볼 수 없음.
- 단원평가·활동지 채점: 학생 그림이 맨 앞, 그 뒤에 공통 글(지시·정답표·평가지 글 최대 1만 2천 자·문항 기준). `gradePrompt`는 학생 줄을 이미 끝에 두었지만 그림이 앞이라 캐시가 안 됨.
- `callApi`(Claude): `content: [...images, { text }]`, `cache_control` 없음, 사용량(usage)을 읽지 않음.
- 단원평가·활동지는 일꾼 2명 고정, 한도(`rate_limited`)에 한 번 걸리면 채점 전체를 멈춤. 평가지 채점은 이미 `conc()`(처음 6, 막히면 절반)로 늘고 줆.
- 그림은 이미 긴 변 1568px·JPEG 0.85, 쪽마다 한 번만 만들어 둠(`p._enc`) — 그대로 둠.
- Claude 5.5 모델: 캐시는 **512토큰부터**, 캐시 읽기는 기본 값의 0.1배 이하(Opus 5.5는 0.05배), 쓰기 1.25배(5분), **캐시 읽기는 분당 입력 한도(ITPM)에 세지 않음**. Gemini·OpenAI는 앞부분이 같으면 스스로 캐시(OpenAI 1024토큰부터).

## 3. 공통 부분을 앞에 (모든 회사)

### 3.1 요청 순서
`generate(prompt, { images, shared: { text, images } })` — `shared`는 학생마다 똑같은 부분.

| 회사 | 보내는 차례 |
|---|---|
| Claude | `[공통 그림…, 공통 글(+cache_control), 학생 그림…, 학생 글]`. 공통 글이 없으면 마지막 공통 그림에 `cache_control`. 공통이 없으면 지금과 같음 |
| Gemini | `parts: [공통 그림…, 공통 글, 학생 그림…, 학생 글]` (스스로 캐시) |
| OpenAI | `content: [공통 그림…, 공통 글, 학생 그림…, 학생 글]` + `stream_options: { include_usage: true }`. 공통이 없으면 지금 차례(글 → 그림) 그대로 |
| 업스테이지 | 그림은 글자로 읽어(OCR) 앞에 붙임. **같은 그림은 다시 읽지 않음**(그림 객체마다 기억, 앱을 끄면 지움) |
| Claude 계정 | 공통 글 + 학생 글을 이어 붙이고 그림도 공통 → 학생 차례로 붙여 지금처럼 보냄 |

- 캐시는 5분(기본 `ephemeral`). 한 반 채점은 몇 분 안에 이어지므로 1시간 캐시는 쓰지 않음(쓰기 값이 2배).
- 공통 부분은 같은 채점 안에서 **글자 하나도 다르지 않게**: 학생 번호·쪽 수·검토할 문항처럼 학생마다 다른 것은 모두 학생 글로.

### 3.2 채점별 공통 / 학생 부분

| 곳 | 공통(shared) | 학생(own) |
|---|---|---|
| 단원평가 채점 | 지시·정답표·평가지 글·할 일·출력 모양 | 학생 답안 그림 + `[학생] n번 — 바로 위 그림이 이 학생의 평가지예요` |
| 단원평가 검토 AI | 검토 지시·**정답표 전체**·평가지 글·출력 모양 | 학생 그림 + 학생 번호·다시 볼 문항과 메인 AI가 읽은 것 |
| 활동지 채점 | 지시·활동지 정보·문항과 기준·채점 규칙·출력 모양 | 학생 그림 + `바로 위 그림 n장은 한 학생의 활동지(차례대로)` |
| 활동지 검토 AI | 검토 지시·문항과 기준·출력 모양 | 학생 그림 + 다시 볼 칸 |
| 평가지 채점 | **기준 그림(최대 6장)** + 지시·평가 정보·채점 기준·할 일·출력 모양 | 학생 그림 + `바로 위 그림 n장은 한 학생의 수행평가지` |
| 평가지 검토 AI | 기준 그림 + 검토 지시·평가 정보·채점 기준 | 학생 그림 + 메인 결과 |

- 프롬프트 글은 그림 차례에 맞게 고침: 「이 글 **앞의** 그림 n장은 정답·채점 기준」, 「학생 그림은 이 글 **뒤**에 와요」.
- AI로 가는 것은 그대로: 이름 칸을 가린 그림·번호·정답·기준만. 차례만 바뀜.

## 4. 동시 채점 (단원평가·활동지)

- 처음 **3명**, 3명 연달아 잘되면 1명씩 늘려 **최대 4명**. Claude 계정이면 2명 고정.
- 한도(`rate_limited`)에 걸리면: 그 학생은 실패로 두지 않고 **줄 맨 앞에 다시**, 동시 수를 절반(최소 1), **20초 쉰 뒤** 이어 감(화면 「AI 한도에 걸려 잠깐 쉬어요」). **1명씩인데 세 번 연달아** 걸리면 지금처럼 멈추고 까닭을 알림.
- 키 틀림(`auth`)·사용 한도(`quota`)는 지금처럼 바로 멈춤. [멈추기]는 쉬는 중에도 바로 멈춤.
- 평가지 채점의 `conc()`는 그대로(이미 늘고 줆).

## 5. 사용량 한 줄

- 회사 답에서 사용량을 읽음: Claude `message_start.message.usage`(input·cache_creation·cache_read) + `message_delta.usage.output_tokens`, Gemini `usageMetadata`(promptTokenCount·cachedContentTokenCount·candidatesTokenCount·thoughtsTokenCount), OpenAI 마지막 조각 `usage`(prompt_tokens·prompt_tokens_details.cached_tokens·completion_tokens). 업스테이지 채팅도 `usage`가 오면 읽음. Claude 계정은 없음.
- 한 번의 채점(검토 AI 포함, JSON 다시 묻기 포함)을 모아 끝나면 그 화면에: **「AI 사용량: 보낸 양 약 4.2만 토큰(그중 83%는 캐시로 싸게) · 받은 답 0.9만 토큰」**. 캐시가 없으면 괄호를 뺌. 1만 미만은 「3,210 토큰」.
- 그 평가(단원평가 `t.aiUse`, 활동지 `a.aiUse`, 평가지 채점 기록 `aiUse`)에 `{ at, sent, cached, out }`(숫자만)으로 남겨, 다시 열어도 「지난 채점 AI 사용량」으로 보임. 다시 채점하면 바뀜.
- 돈(원)으로는 보이지 않음(모델·환율·요금이 바뀜).

## 6. 구조

- 새 `core/ai-wire.js`(화면 없음, 시험): `claudeContent`·`geminiParts`·`openaiContent`(공통/학생 차례·캐시 표시), `flatten`(업스테이지·Claude 계정용), `readUsage(provider, event, acc)`, `newMeter()`(`add`·`total`·`text`), `useText(u)`.
- 새 `core/ai-pool.js`(시험): `runPool(run, task, { start, max, wait, giveUp, sleep, onWait })` — `task`가 `'rate'`를 돌려주면 다시 줄에·절반·쉼.
- `evaluate.js` `callApi`·`generate`: `shared`·`meter`를 받아 `ai-wire`로 내용을 짜고 사용량을 `meter`에 더함. `window.SSAM_WIRE`(모듈이 넣음)를 부를 때 씀. 업스테이지 OCR은 그림마다 기억.
- `core/ai.js` `generate`·`generateJSON`, `core/ai-review.js` `reviewJSON`: `shared`·`meter`를 넘김.
- `unit-ai.js` `gradeParts`·`gradeReviewParts`, `activity-ai.js` `gradeParts`·`reviewParts`, `evaluate.js` `grGradeParts`·평가지 검토: 공통/학생으로 나눔(옛 `gradePrompt`는 둘을 이어 붙인 글을 돌려줌).
- 시험 도우미 `mockClaude`: 글 조각을 모두 이어 `prompt`로, `content`도 넘김, 사용량(usage) 이벤트를 보낼 수 있게.

## 7. 오류·예외

- 공통 글이 512토큰보다 짧으면 Claude는 캐시를 하지 않을 뿐 오류 없음(값도 그대로).
- 검토 AI가 메인과 다른 모델이면 캐시도 따로(모델마다 캐시) — 그대로 둠.
- 한도 쉬는 동안 다른 메뉴로 가도 채점은 이어 감(지금과 같음).
- 사용량을 못 읽으면(오래된 응답 모양) 그 요청은 0으로 셈. 모두 0이면 줄을 보이지 않음.

## 8. 시험

- 단위: 회사별 차례·`cache_control` 자리(공통 글/마지막 공통 그림/공통 없음), OpenAI `include_usage`, `flatten`, `readUsage` 세 회사, 미터 합·문구(만·캐시 %·0이면 빈 글), `runPool`(최대 동시 수, 늘리기, 한도 → 다시 줄·절반·쉼, 1명에서 세 번 → 멈춤, 멈추기), 프롬프트 나누기(공통이 학생마다 같고 학생 번호는 학생 글에만, 이어 붙인 글은 옛 것과 같은 내용).
- 화면(가짜 AI): 단원평가·활동지·평가지 채점 요청이 「공통 → 학생」이고 공통 글에 `cache_control`, 학생마다 공통 글이 같음 · 동시 요청이 4를 넘지 않음 · 한 학생이 한도에 걸려도 채점이 끝까지 감 · 끝나면 「AI 사용량」 줄과 새로고침 뒤 「지난 채점」 · 평가지 채점에서 기준 그림이 앞.
- 진짜 AI로는 시험할 수 없음 — 캐시가 되는지는 실사용 때 사용량 줄(캐시 %)로 확인.
